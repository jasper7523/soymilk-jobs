# 豆漿接案表 v2

網址：`https://jasper7523.github.io/soymilk-jobs/v2/`
舊版還在根目錄 `https://jasper7523.github.io/soymilk-jobs/`，兩邊互不影響。

## 現在的狀態：唯讀預覽

v2 頁面會先找試算表裡叫 `v2` 的分頁。找不到，就讀舊分頁即時換算成新格式給你看（狀態、報酬、地點是猜的），**不能存**。
試算表 ID 跟舊版共用同一個 `localStorage` 鍵，所以你和豆漿的手機上打開 `/v2/` 應該直接看得到資料，不用重設。

## 要能寫入：三步，做一次

1. **搬家**
   試算表 → 擴充功能 → Apps Script → 把「程式碼.gs」全選刪掉，把 `gas_v2.js` 整個貼進去。
   在**編輯器裡**把 `var KEY = '';` 的引號中間填上你的通行碼，存檔。
   ⚠️ 不要把通行碼寫回 repo 裡那個 `gas_v2.js`——那個檔會上公開的 GitHub。
   （更好的做法：專案設定 → 指令碼屬性 → 新增 `KEY`＝通行碼，這樣改密碼不用重新部署。）
   上方函式選單選 `migrateFromV1` → 執行（第一次會要求授權）。
   跑完會多一個 `v2` 分頁。舊分頁一個字都不會動。

   ⚠️ **搬家一輩子只要成功一次。** 之後更新程式碼，只要「重貼 + 重新部署」，**不要再跑搬家**。
   `migrateFromV1()` 現在會自我保護：`v2` 只要有資料就直接擋下來，不會蓋掉你們後來改的東西。
   真的要重搬才執行 `migrateFromV1_REDO()`，它會先把現有 `v2` 另存成「v2_備份_日期時間」分頁。

   舊資料永遠在第一個分頁，搬幾次都不會損傷；會不見的只有「搬家之後你們在 v2 裡改的東西」。
   萬一真的被蓋掉：試算表 **檔案 → 版本記錄 → 查看版本記錄**，挑重搬之前的時間點就能還原。

2. **部署**
   部署 → 新增部署 → 類型「網頁應用程式」→ 執行身分「我」→ 存取權「任何人」→ 部署。
   複製那串 `https://script.google.com/macros/s/AKfy…/exec`。

3. **設定連結**
   組一條連結，用 LINE 傳給豆漿，她點一下就設好：

       https://jasper7523.github.io/soymilk-jobs/v2/#s=試算表ID&g=AKfy那串部署ID&k=通行碼&me=豆漿

   你自己用 `&me=簡`。`g=` 可以只放 `/s/` 和 `/exec` 中間那段，也可以放完整網址。
   點開後網址列的 `#` 會自動清掉，不會留在書籤裡；設定存在那台手機的瀏覽器裡。

## 安全性

- 部署設「所有人」的意思是：**拿到那串部署網址的人**不用登入就能呼叫它。網址不會被列在任何地方、搜尋不到，但會存在她手機的瀏覽器和你傳給她的 LINE 訊息裡。
- 所以加了通行碼：沒帶正確通行碼的請求一律拒絕（讀和寫都是）。部署網址外流也寫不進去。
- 腳本只碰這一份試算表，沒有刪除功能，最壞情況是多幾列垃圾或被改幾格。碰不到你 Google 帳號的其他東西。
- 試算表本身目前是「知道連結的人可檢視」（舊版就是這樣，前台才讀得到）。要更緊，可以把試算表改成「限制」：前台讀不到 gviz 時會自動改走 Apps Script 讀（要通行碼），讀取會慢 1–2 秒。
- **舊資料的 catbox 連結**：舊版把 92 份報名表 PDF 上傳到 `files.catbox.moe`，那些 PDF 裡有豆漿填的姓名、年齡、手機、Email、LINE ID。搬家後 `pdf_url` 改存本機檔名，新表不再指向 catbox，但**那些檔案還在 catbox 上**，要另外去刪（catbox 沒帳號的話刪不掉，只能靠網址失效——這件事還沒解決）。

之後前台改版只推 `index.html`，Apps Script 不用再碰。

## 第四步（選用）：PDF 報名表匯入

取代舊的 `sync_jobs.py`。差別：

| | 舊 sync_jobs.py | 新 sync_pdf.py |
|---|---|---|
| 案名 | 檔名 | 讀 PDF 第一段標題 |
| 內容 | 沒有 | PDF 全文進「原始訊息」 |
| 金額／期限 | 沒有 | 抓得到就自動填 |
| PDF 原檔 | 上傳 catbox.moe（公開） | **留在本機，不上傳** |
| 個資 | 原樣公開 | Email／手機／身分證遮掉，表單罐頭字濾掉 |

做法：

1. 在 `v2/` 建 `settings.json`（已在 .gitignore，不會進 git）：

       {"gas_url": "第二步那串網址",
        "key": "你的通行碼",
        "pdf_dir": "D:\\Agent_Hub\\agents\\Marketing_Agent\\marketing\\00_Job Dashboard",
        "who": "簡"}

2. 先試跑，不寫入：`python sync_pdf.py --dry`
   產出 `_preview.txt`，逐筆列出抓到的案名、金額、期限、訊息前 300 字。看過再決定。
3. 沒問題就跑 `python sync_pdf.py`。

**重跑安全。** 靠 PDF 檔名比對：那一列已經在表裡 → 只補**原本是空的**欄位，你們手打過的東西不會被蓋掉；不在 → 新增。「… (2).pdf」「… (3).pdf」視為同一份。

目前實測（92 份 PDF）：重複檔名跳過 3 份，處理 89 份，抓到金額 20 份、抓到發文期限 15 份。抓不到的一律留空，不亂猜——寧可空白也不要填錯數字。

## 試算表 `v2` 分頁欄位

| 欄位 | 內容 |
|---|---|
| id | `J2026-0901-04`，主鍵，Apps Script 自動編 |
| title | 案件名稱，唯一必填 |
| status | `inquiry` 邀約中 / `scheduled` 待拍 / `to_deliver` 待交 / `to_publish` 待發 / `done` 結案 / `declined` 婉拒 |
| source | 邀約 / 報名 |
| tag | KOC、探店、拍攝… 自由文字 |
| shoot_date | `2026/09/17 19:30`、`2026/09/15 全天`、`2026/08/11 半天`，純文字 |
| location | 地址或店名 |
| contact | IG @帳號、LINE ID |
| pay_type | 有酬 / 互惠 / 兩者 / 未定 |
| pay_amount | 數字 |
| deliverable | 要交什麼 |
| due_deliver | 交件期限 `YYYY/MM/DD` |
| due_publish | 發文期限 `YYYY/MM/DD` |
| post_url | 發文連結，填了自動結案 |
| raw_message | 廠商原始訊息整段 |
| note | 自己的備註 |
| pdf_url | 報名表 PDF 的檔名（不含 .pdf）。匯入靠它認人，不要手改 |
| created_at / updated_at / updated_by | 自動 |

## 頁面規則

- **要交的**：待交＋待發，照交件期限（沒填就用發文期限）排；逾期紅、三天內橘、沒填灰排最後。
- **接下來要拍**：待拍，照拍攝日期排。日期過了還在待拍 → 標「拍了嗎？」，不自動改。
- **邀約中**：照收到日，新的在上；超過 30 天變灰。
- **結案／婉拒**：折疊。
- 邀約中填了拍攝日期 → 自動變待拍。貼了發文連結 → 自動結案。
- 每次儲存後都重新讀試算表確認那筆真的在，不再前端假裝成功。
